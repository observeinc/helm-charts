# OSS collector examples must match the chart

`examples/oss-collector/` is for customers who run a plain `otelcol-contrib` collector on Kubernetes instead of the Observe Agent Helm chart. `collector/` contains the collector configurations, and `helm/` contains values that deploy the same configurations with the upstream OpenTelemetry Collector Helm chart. Both are generated by `scripts/oss-collector/generate.sh`, from the Observe Agent chart rendered into `examples/oss-collector/rendered/`. The Observe documentation links to them. They must process data the same way the chart does.

## When this rule applies

Check this rule when a pull request changes any of:

- `charts/agent/templates/**` collector configuration: processors, pipelines, receivers, exporters, or the environment variables they read
- `charts/agent/templates/**` collector workloads and RBAC: container arguments, environment variables, volumes, security context, resources, ports, Services, or ClusterRole rules
- `charts/agent/values.yaml` defaults that change the rendered collector configuration
- `charts/agent/Chart.yaml` `appVersion`, which changes the collector version the examples are validated against, and which `scripts/oss-collector/upstream-chart.yaml` must follow
- `examples/oss-collector/**` or `scripts/oss-collector/**`
- `test/verify_oss_examples.sh` or `test/lib/deployment_environment.sh`

## What to check

1. **The examples are regenerated.** `make generate-examples` runs `scripts/oss-collector/generate.sh`, which renders the chart with `scripts/oss-collector/values.yaml` into `examples/oss-collector/rendered/` and turns the rendered `forwarder`, `node-logs-metrics`, and `cluster-metrics` ConfigMaps into `examples/oss-collector/collector/{forwarder,node,cluster-metrics}.yaml`, keeping only the pipelines and extensions listed in `collectors.yaml`, and writes `examples/oss-collector/helm/*-values.yaml` from the same configurations and the rendered workloads. If the pull request changes one of those collectors or their workloads, the generated files must change in the same pull request. Flag hand edits to `examples/oss-collector/collector/*.yaml` or `examples/oss-collector/helm/*.yaml`.
2. **New chart-only pieces are handled.** If the pull request adds a component or environment variable that only works inside the chart (for example a variable that the observe-agent binary sets at startup, a fleet or self-monitoring component, or an Observe-specific processor) to a listed pipeline, it reaches the examples. Check that `scripts/oss-collector/otel-config.yaml` replaces it, or that it validates with upstream `otelcol-contrib`. The generator fails on an environment variable it can't describe; a new variable needs an entry in `describe_env` in `generate.sh`.
3. **The example still covers the change.** If the pull request adds a feature that collector users need, check whether `values.yaml` enables it and whether `collectors.yaml` lists its pipeline. If not, ask whether it should.
4. **Behavior is tested.** Changes to how resource attributes such as `deployment.environment.name` are set or ordered must keep `test/verify_oss_examples.sh` passing, and should extend it when they add new behavior.
5. **No credentials.** Examples must read endpoints and tokens from environment variables (`${env:OBSERVE_COLLECTION_URL}`, `${env:OBSERVE_TOKEN}`), never contain a real collection URL or ingest token.
6. **The host example may need the same change.** The host example lives in `observeinc/observe-agent` under `examples/oss-collector/`. If the change also applies to the agent's bundled configuration, mention that the agent and its example need a matching change.
7. **Documentation.** If the change alters what customers must deploy or configure (environment variables, permissions, mounts, ports), mention that `examples/oss-collector/README.md` and the "Configure your own OTel collector" pages on docs.observeinc.com may need an update.
8. **The upstream chart version follows the agent.** `scripts/oss-collector/upstream-chart.yaml` pins the OpenTelemetry Collector chart version whose `appVersion` is the collector version of the Observe Agent release that `charts/agent` deploys. If the pull request changes `appVersion` to a release with a different collector version, check that `upstream-chart.yaml` moves to the matching chart version.
